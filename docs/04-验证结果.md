## 0. 验证方法与其诚实边界

### 方法

真实 DSH 桌面窗口**无法在无人干预下自动重启并录像**（重启即关闭本会话）。因此采用**结构等价验证**：

1. 造一个 `_verify/harness.html`，复刻桌面版前端拿到注入后的真实执行路径：
   - 加载与 `dist/index.html` 一致的空壳（只有 `<div id="root">`）
   - 复刻 `serveWebDocument` 注入的 `__DSH_BOOT_READY__` 行
   - 复刻前端 `hM(e, n)` 注入行解释器（`global` / `script` / `style` / `html` 四种 case 全部照抄）
   - 复刻前端自带加载页 `tM` 的关键特征：`#root` 下有一个 `data-dsh-boot` 元素
   - 复刻 AppFrame 结构：三列 grid（`280px / minmax(400px,1fr) / 340px`）、`[data-shell-overlay]`、三个 `[data-slot]` 锚点且**均为 `display:contents`**
2. **注入的是未经改写的真实 `lib/boot-anim.css` 与 `lib/boot-anim.js`**（`run.mjs` 直接读取文件内容拼进 `__INJECTIONS__`）。这一点很重要：验证的不是「一个类似实现」，而是**即将上线的那个文件本身**。
3. 真实时间采样：从 `goto` 起按目标时刻截图，同时读取 `getComputedStyle`。

### 诚实的边界

| 未验证项 | 原因 |
|---|---|
| 真实 DSH 窗口中的最终观感 | 需重启桌面版；重启会终止当前会话 |
| 真实桌面版的 IPC 往返时机 | 同上 |
| 注入晚于 React 首次挂载 | 理论推断：舞台 `z-index` 极高 + `waitApp` 会等 UI 就绪，最差是 UI 闪一帧后被覆盖 |

**上表三项在本文中一律标注为「未验证」，不从等价验证的结果里外推。**

## 5. 无闪烁论证

需求要求「过渡到 UI 可交互状态无跳变、无闪白/闪黑」。本实现从构造上排除：

| 风险 | 为什么不会发生 |
|---|---|
| **闪白** | 动画全程幕布是纯黑 `#000`；揭幕瞬间露出的是**真实 UI**，其底色由 `body` 的 `var(--dsw-alias-bg-base)` 决定。而壳层 `createWindow` 用 `show:false` 等到 `ready-to-show` 才显示窗口 —— 窗口第一次可见时，页面已有内容，不存在「白底闪烁」窗口 |
| **闪黑（尾部）** | 幕布退场与鲸鱼淡出**并行**，它们在 ⑤⑥ 结束时同帧到达终态；紧接 ⑦ 的 UI 入场从位移 + 透明起步，不会出现「黑 → 白 → 内容跳入」的中间态 |
| **UI 抖动** | ⑦ 只动 `transform` 与 `opacity`，两者都在合成层，不触发布局与重绘（01 号文档 B2「Never animate layout properties」/ C3 MDN 结论） |
| **重复播放** | 注入 `script` 行只在前端 boot 流程执行一次；UI 之后的重渲染不会重放（满足 01 号文档 B1「One-shot only」） |
| **黑幕卡死** | 4 条安全网：`prefers-reduced-motion` 直接跳过 / 用户任何输入即跳过 / `finally` 必 `teardown` / 20 秒兜底定时器 |

### 7.5 修复的一个真实缺陷（安装时才发现）

**原 `install.ps1` 会弄坏 profile。** PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写入 UTF-8 BOM，而 BOM 会让 Node 的 `JSON.parse` 直接抛 `Unexpected token` —— 加载器读 profile 用的正是 `JSON.parse(readFileSync(path, "utf8"))`，一旦写入 BOM，**桌面版下次启动会读不出 profile**。

实测对比：

```
Set-Content -Encoding UTF8      -> 前 3 字节 239,187,191（有 BOM）-> Node JSON.parse 失败
WriteAllText(UTF8Encoding false) -> 前 3 字节 123,34,97（无 BOM）   -> Node JSON.parse OK
```

现已改为 `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding $false))`，并在写入后**回读头三字节自检**，若为 BOM 立即抛错中止。`uninstall.ps1` 同样处理。

此外把 junction 的删除从 `Remove-Item -Recurse` 改为 `(Get-Item -Force).Delete()` —— 前者对 junction 会**穿透删除目标目录内容**，是危险操作。

在鲸鱼轮廓勾勒完成、横线展开之前插入的一段过场，按确认后的分镜实现。

### 8.1 时序与实测

| 步 | 内容 | 实测时间窗 |
|---|---|---|
| ② | 鲸鱼淡出后重新组合 | ④ 收笔 + 240ms 起 |
| ③ | 鲸鱼左移让出中央 | +300ms 起，移出约 366px |

### 8.3 实现过程中修掉的两个真实缺陷

这两个都是**只有跑出来才会发现**的：

**① 光带不可见（两个叠加原因）**

第一版用 `mix-blend-mode: screen` 让光带叠在字标上。实测逐帧截图**字节数完全相同**——
画面上什么都没变。两个原因：

- 渐变用了 `gradientUnits="userSpaceOnUse"`，坐标 0→260，而光带矩形在 x=-160..100，
  投影后正好落在渐变的全透明区间，**光带整个不存在**；
- 即便渐变对了，屏幕混合下 `screen(白, 白) = 白`，白色光带叠白色字标也**恒等于没有效果**。

改法：光带改为**遮罩**——字标本体压暗（`opacity: .32`），另叠一层同形的纯白副本，
由移动的光带遮罩裁切，只有扫过的部分高亮出来。这才是「一道亮带掠过字面」。

**② 鲸鱼与字标重叠**

初版把鲸鱼左移写死 180px，字标居中。实测截图显示两者压在一起。
改为**按实测宽度动态计算**：先定字标高度，再读鲸鱼 `getBoundingClientRect().width`，
算出「鲸鱼 + 间距 + 字标」整组居中时鲸鱼该在的位置。
1440 宽下校验：位移 -366px，组范围 354..1086，组中心 720 = 视口中心，间隙 44px。

### 8.4 一处按需求修正的设计

需求原文是「先**打开/展开**，随后画面**变为白色**」。我最初理解成要在展开之前
铺一层白场，结果造成「黑 → 白 → 黑 → UI」的闪烁，与「衔接无跳变」的验收标准相悖。

按需求顺序重读后确认：**「展开」与「变白」是同一个动作** —— DSH 界面本身就是白的，
展开露出皮肤的同时就完成了变白。因此删掉了多余的白场层。
