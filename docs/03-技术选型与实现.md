# 03 · 技术选型与实现说明

> 阅读顺序：[01 检索清单](01-方案检索清单.md) → [02 技术对比](02-UI入场动画技术对比.md) → **本文**

---

## 1. 一句话选型

**做一个宿主侧插件 `local/dsh-boot-anim`，经 DSH 自带的 `webserver/index-inject` 通道注入 2 行数据（`style` / `global` / `script`），把整套动画作为「零依赖 IIFE + 纯 CSS + SVG + Web Animations API」在页面内自绘。**

不新增 HTTP 路由、不注入静态资源、不改 DSH 任何源码、不动 `app.asar`、不加任何 npm 依赖、不依赖任何 hash 类名。

---

## 2. 为什么是这个方案：三条候选路径的淘汰过程

| 候选 | 做法 | 淘汰原因 |
|---|---|---|
| **A. 解包重打包 `app.asar`** | 解开 121 MB 的 asar，改 `lib/main.js` 加一个真正的启动窗口，再打回去 | ① 每次 DSH 自动更新都会覆盖（`app-update.yml` 指向 `download.deepseek.com/dsh-desk/feeds/win-x64/`）；② 121 MB 重打包有损坏安装的风险；③ 无法干净回滚。**淘汰。** |
| **B. 改 `resources/app/` 目录** | 直接改那个看似「解包副本」的目录 | **该目录是陈旧副本，运行时根本不加载。** 宿主进程命令行是 `--app-path=...resources\app.asar`，所有代码从 asar 走。改了等于没改。**淘汰。** |
| **C. 宿主侧插件 + index 注入** | 写一个 DSH 插件，订阅 `webserver/index-inject`，把动画作为注入行送进页面 | **采纳。** 走 DSH 官方插件契约，更新后不失效；不碰任何原始文件；卸载即还原。 |

### 选 C 的决定性依据：把桌面版的加载链路完整读了一遍

这一步是整个任务的分水岭，因为**桌面版和白盒直觉不一样**：

```
resources/app.asar/lib/main.js
  ├─ serveWebDocument()
  │    直接 readFile(dist/index.html)，**不调用 renderIndex()**
  │    只在 <head> 里塞一行 __DSH_BOOT_READY__
  ├─ protocol.handle(SCHEME)   hostname === "app"
  │    → 从 <resources.dsh>/node_modules/@deepseek-ai/dsh-web-frontend/dist 取文件
  └─ DESKTOP_IPC.boot 返回 { injections, streamBaseUrl }
               ↑ 值来自 ctx.webServer.collectIndexInjections()
```

关键在最后一行：**桌面版虽然不把注入行渲染进 HTML，但它把同一张行表通过 IPC 交给了页面**。前端 `dist/assets/index-*.js` 里有一个解释器（实读原文）：

```js
async function hM(e, n) {
  for (const o of e) switch (o.kind) {
    case "global":  globalThis[o.name] = o.value; break;
    case "script":  /* 造 <script>，textContent = o.text，插入 head 或 body */ ; break;
    case "script-src": await n(o.src); break;
    case "style":   /* 造 <style>，textContent = o.text，插入 head */ ; break;
    case "html":    /* insertAdjacentHTML */ ; break;
  }
}
```

**结论：只要往 `collectIndexInjections()` 的表里 push 行，桌面端就会在页面里执行它 —— 无论内容多长，也无论有没有 HTTP 路由。** 这条路径让方案 C 变得极其干净：整个插件只有 30 行宿主代码。

### 顺带确认的两个前提

1. **白屏问题壳层已经解决**。`lib/main.js` 里 `createWindow(preload, show = false, primary = false)`，主窗口由 `createMainWindow()` 以 `createWindow(appPreload, false, true)` 创建（`show:false`），直到 `enterWorkspace()` 才 `window.show()`。这正是 01 号文档 C2 节查到的 Electron 标准解法 —— 所以**分镜① 取黑屏是安全的**，壳层给的是一块稳定画布。
2. **动画只在页面加载时播一次**。注入的 `script` 行只在前端 boot 流程里执行一次，UI 之后怎么重渲染都影响不到它 —— 这正好满足 01 号文档 B1 的「One-shot only」铁律，且不需要 cookie / localStorage 门控（调试期重载页面即可重放）。

## 3. 鲸鱼轮廓：与原图标逐字节一致

需求要求「轮廓勾画需与原图标一致」。做法是**直接把原 path 抄过来**，不是照着重画：

- **来源**：`@deepseek-ai/dsh-client-ui-primitives` 的 `FISH_LOGO_PATH`（从 `app.asar` 实读提取）
- **规格**：3448 字符；4 条子路径（`M…C…Z` × 4）；`viewBox="0 0 23.16 17.04"`
- **用法**：同一段 `d` 被**渲染两次**，各自套一个 `clipPath`：
  - `#ba-clip-l` 只留 `x < 11.58`（左半）
  - `#ba-clip-r` 只留 `x > 11.58`（右半）

  两条路径的 `stroke-dashoffset` **反向**（`-1 → 0` 与 `+1 → 0`），于是描边从中间同时向两端铺开 —— 这就是分镜④「两条线分别构筑成鲸鱼」。

> 侧边栏图标（`sidebar.brand.mark` 的 fallback）与对话区 hero 用的是**同一个** `FishLogo` 组件，所以「与现有图标一致」是构造性成立的，不是视觉近似。

### 一个必须解决的几何问题

分镜③ 的「两条线」和分镜④ 的「线构筑成鲸鱼」需要**同一个元素**从「一条横线」连续变形成「鲸鱼轮廓」。做法是：

- 鲸鱼组套 `transform: scaleY(0.018)` → 压成一条约 2px 的横线（正是分镜③ 末端状态）
- 然后 `scaleY: 0.018 → 1`，同时两条半路径描边展开 → 分镜④

但压扁会把描边一起压细到看不见。**解法是 `vector-effect: non-scaling-stroke`**：描边宽度不再随 transform 缩放，压平时它仍是一条实心横线。这条工程细节让 ③ 和 ④ 能用同一个元素无缝衔接，不必切换 DOM。

## 4. 七段分镜的实现映射

| 分镜 | 实现 | 元素 |
|---|---|---|
| ① 黑屏 | 两层 `.ba-curtain`（上/下各 50% 高，纯黑 `#000`），初始即全黑 | `.ba-top` / `.ba-bottom` |
| ② 中央出现鲸鱼 | `whale` 从 `opacity:0 scale(.86)` → `opacity:1 scale(1)`，延迟 220ms | `.ba-whale` |
| ③ 转全黑、两线向中间延伸 | whale 淡出 240ms；两条线各占半屏，`transform-origin` 钉在外侧边缘，`scaleX(0)→scaleX(1)` | `.ba-line-l` / `.ba-line-r` |
| ④ 两线构筑成鲸鱼并勾轮廓 | `scaleY .018→1`（1180ms）+ 两条半路径 `stroke-dashoffset` 反向展开（1280ms） | `.ba-whale-g` / `.ba-p-l` / `.ba-p-r` |
| ⑤ 中央横线上下展开，画面一分为二 | `.ba-seam` 横向扫出后淡出；两层幕布 `height: 50% → 0%`（上幕向上退、下幕向下退） | `.ba-seam` / `.ba-curtain` |
| ⑥ 同时鲸鱼消失、露出皮肤 | `whale opacity 1→0`（900ms，延迟 260ms），与幕布退场并行 | `.ba-whale` |
| ⑦ UI 由外向内、环环平移入场 | 三段波次：外层三列 → 列内主块 → 主块内内容块 | 见 §5 |

**总时长实测约 5.6 秒**（不含等待 UI 就绪的时间），对齐 01 号文档的复核发现：官方**桌面场景**开机动画 `steam_os_startup.webm` = 5.000s，而非掌机的 4.008s。

## 5. ⑦ 的三个关键设计

### 5.1 用状态闸门，而不是定时器

分镜④ 收笔后**不立刻揭幕**，而是轮询 `appReady()`：

1. 出现 `[data-shell-overlay]`（应用主框架已挂载的确定信号）→ 立即揭幕
2. 或 `#root` 下出现**非 `data-dsh-boot`** 且尺寸 > 320×240 的子节点 → 立即揭幕
3. 或超时 9 秒 → 揭幕

这样慢启动不会「动画放完露空白」，快启动也不会「UI 早好了还压着黑幕」。这是同时满足「无跳变」与「不拖慢」的关键。

### 5.2 怎么在没有稳定类名的情况下找到 UI 分区

DSH 前端是 CSS Modules（hash 类名）+ 打包产物，**没有可挂钩的类名**。链条是：

```
document.querySelector('[data-shell-overlay]')   ← AppFrame 里唯一的语义锚点
        .parentElement                            ← 就是 AppFrame 的三列 grid 容器
        .children → 按 getBoundingClientRect().left 排序
                 → 最左 = 侧边栏、中间 = 对话列、最右 = 右栏
```

`data-shell-overlay` 这个属性是实读 `dsh-client-ui-layout` 源码确认的，同族还有 `data-shell-leading`。三列容器的内联样式含 `gridTemplateColumns`，可作二次校验。

### 5.3 `[data-slot]` 不能当动画目标

`@deepseek-ai/dsh-client-ui-renderer` 里原文：

```js
/** Anchor style shared by every outlet wrapper: display:contents keeps the
  * wrapper out of layout ... so the anchor is purely addressable surface. */
const ANCHOR_STYLE = { display: "contents" };
```

**`display: contents` 的元素没有盒子** —— `getBoundingClientRect()` 返回全 0，拿它做动画目标等于空操作，而且**不会报错，静默失效**。

本实现因此加了 `collectBlocks()`：**穿透 `display:contents` 中间层往下钻，只收「有盒子且够大」的元素**。修好后实测三层波次目标数为 **3 列 / 5 内层 / 2 深层**（见 04 验证报告）。

## 6. 终态皮肤适配

需求要求「落入 DSH 默认白色底色/皮肤，或落入现有 UI 中已装配的皮肤」。做法是**不指定任何颜色，直接借皮肤变量**：

```css
[data-dsh-boot-anim] {
  --ba-bg: var(--dsw-alias-bg-base, #fff);   /* 皮肤定义的主底色，回退到白 */
}
```

- 幕布退场后**没有任何 DOM 残留**（舞台整体 `remove()`），露出的是真实 UI 本身 —— 所以「露出的皮肤」在构造上就等于「已装配的皮肤」，不存在样式回退问题。
- 动画期间用内联样式把内建加载页（`[data-dsh-boot]`）按住：`opacity: 0 !important`，收尾时 `removeProperty` 还原。用 `!important` 是为了不依赖任何 CSS 优先级猜测。
- 深色主题无需改动：幕布本就是黑色、鲸鱼本就是白色描边，与皮肤无关。

## 7. 降级与安全网

| 情形 | 行为 |
|---|---|
| `prefers-reduced-motion: reduce` | CSS 里 `display: none !important`；JS 里 `run()` 首行直接 `teardown()` 结束 |
| 用户在动画中按键 / 点击 / 滚轮 | 立即跳到揭幕（`requestSkip`），不阻断操作 |
| 任何一环抛异常 | `finally` 里必定 `teardown()`，界面绝不永久压在黑幕下 |
| 总时长超 20 秒 | 兜底 `setTimeout` 强制 `requestSkip()` |
| `Element.animate` 不可用 | `play()` 返回 `null`，`settle()` 立即 resolve，动画跳过但不卡住 |
| 注入晚于 React 首次挂载 | 舞台 `z-index: 2147483000` 全屏覆盖；且 `waitApp()` 会等到 UI 就绪 |
